# 创建型模式之单例模式（Singleton）

一般来说， 单例模式有 7 种主流的实现方式。 

1. **饿汉式**：类加载时就初始化实例，线程安全，但可能造成资源浪费。
2. **懒汉式（线程不安全）**：延迟加载，但多线程环境下不安全。
3. **懒汉式（同步方法）**：通过同步方法保证线程安全，但效率低。
4. **双重检查锁定（DCL）**：减少同步块的使用，提高性能，需注意volatile关键字的使用。
5. **静态内部类**：利用类加载机制保证线程安全，延迟加载。
6. **枚举**：Joshua Bloch推荐的方式，防止反射攻击和序列化问题，线程安全。
7. **ThreadLocal 单例**： 线程级单例。

## 核心概念

单例模式定义：确保一个类只有一个实例，并提供全局访问点。

1. **唯一实例**：类只能创建一个对象。
2. **全局访问**：通过静态方法或变量提供对该实例的访问。

### 关键要素

- **私有构造函数**：防止外部直接实例化。
- **静态实例变量**：保存类的唯一实例。
- **静态访问方法**：提供获取实例的全局访问点。





### **单例模式应用场景**

| **场景**              | **推荐实现方式**             |
| :-------------------- | :--------------------------- |
| 配置管理              | 饿汉式、枚举                 |
| 日志系统              | 静态内部类、双重检查锁定     |
| 数据库连接池          | 双重检查锁定、枚举           |
| 线程池管理            | 静态内部类                   |
| Spring Bean单例作用域 | 容器管理的单例（非传统实现） |
| 缓存系统              | 枚举、双重检查锁定           |
| 硬件资源访问          | 饿汉式、枚举                 |



## 使用场景

单例模式的使用场景非常广泛，尤其是在需要确保系统中某个类只有一个实例，并且该实例需要被全局访问的情况下。以下是单例模式的一些典型使用场景，详细说明如下：



### 1. **配置管理**

- **场景描述**：在应用程序中，配置文件通常只需要加载一次，并且在全局范围内共享。

- **为什么使用单例**：单例模式可以确保配置管理器只有一个实例，避免重复加载配置文件，同时方便全局访问配置数据。

- **示例**：

  ```java
  public class ConfigManager {
      private static ConfigManager instance;
      private Properties config;
  
      private ConfigManager() {
          config = new Properties();
          // 加载配置文件
          try (InputStream input = getClass().getClassLoader().getResourceAsStream("config.properties")) {
              config.load(input);
          } catch (IOException e) {
              e.printStackTrace();
          }
      }
  
      public static ConfigManager getInstance() {
          if (instance == null) {
              instance = new ConfigManager();
          }
          return instance;
      }
  
      public String getProperty(String key) {
          return config.getProperty(key);
      }
  }
  ```

  ```java
      private Map<String, List<String>> permissions;

          permissions = new HashMap<>();
      }
  
      public static PermissionManager getInstance() {
          if (instance == null) {
              instance = new PermissionManager();
          }
          return instance;
      }
  
      public void addPermission(String role, String permission) {
          permissions.computeIfAbsent(role, k -> new ArrayList<>()).add(permission);
      }
  
      public boolean hasPermission(String role, String permission) {
          return permissions.getOrDefault(role, Collections.emptyList()).contains(permission);
      }
  }
  ```

## 单例模式防御技术

#### **防止反射攻击**

```java
public class ReflectionSafeSingleton {
    private static volatile ReflectionSafeSingleton instance;
    
    private ReflectionSafeSingleton() {
        if (instance != null) {
            throw new RuntimeException("Use getInstance() method!");
        }
    }
    
    public static ReflectionSafeSingleton getInstance() {
        // 双重检查锁定实现...
    }
}
```

#### **防止序列化破坏**

```java
public class SerializableSingleton implements Serializable {
    private static final long serialVersionUID = 1L;
    
    private SerializableSingleton() {}
    
    private static class Holder {
        static final SerializableSingleton INSTANCE = new SerializableSingleton();
    }
    
    public static SerializableSingleton getInstance() {
        return Holder.INSTANCE;
    }
    
    // 重写此方法防止反序列化创建新实例
    protected Object readResolve() {
        return getInstance();
    }
}
```





对于我们常见的应用就是应用程序的单次启动，比方说，应用程序只允许打开一次，再次打开时，使用已经打开的应用进行响应。微信PC端，钉钉，还有常用的 Windows 系统的任务管理器。

为什么这么设计，通常情况下，多次打开内容一致，再次打开一个应用就是资源的浪费。

为了节约资源，系统在设计某个类只能有一个实例时， 将使用单例模式。就是创建一个实例后，将不允许再次创建一个新的实例。

在 Java 中如何做到呢？ 首先要关注的是语言如何创建对象。对于 Java 来说， 就是 new 一个对象， 只要控制 new 就可以控制对象的创建。其他语言根据这个情况自行考虑如何实现单例模式，理论是相同的，只是语言的语法不同而已。

比方说我现在有个类，叫做微信 PC 客户端 `WxPcApp`，创建一个对象的方式就是。

```java
WxPcApp wxPcApp = new WxPcApp();
```

这里不需要知道 `WxPcApp` 的具体内容，每次 `new WxPcApp()` 就是一个新的对象创建。

如何控制让自身进行创建对象， 而不是由外部进行创建呢？这里使用到 Java 的封装的属性，并使用私有化构造函数来实现。实际对象 new 的过程， 就是调用构造函数的过程，默认的构造函数就是对象的名字。所以我只需要让外部不能通过构造函数进行创建对象即可。 

```java
class WxPcApp{
	private WxPcApp(){
    }
}
```

既然不允许访问构造函数，就需要该类提供一个方法， 可以返回这个对象实例。

```java
class WxPcApp{
    private static WxPcApp wxPcApp;
    private String startTip;
	private WxPcApp(){
        startTip = String.valueOf(System.curr);
    }
    public static WxPcApp build(){
        if(Objects.isNull(wxPcApp)){
            wxPcApp = new WxPcApp();
        }
        return wxPcApp;
    }
}
```

除了这种方式之外， 还有直接初始化的方式。 

```java
class WxPcApp{
    private static WxPcApp wxPcApp = new WxPcApp();
    private String startTip;
	private WxPcApp(){
        startTip = String.valueOf(System.curr);
    }
    public static WxPcApp build(){
    	return wxPcApp;
    }
}
```

对于这两种方式，又有人给他们定义了两个新的名字，第一个叫做赖汉式，第二个叫做饿汉式。根据名字可以看出来，懒汉式，你不需要的时候， 我啥都不做。饿汉式，只要运行实例，我就给你创建好对象等你来用，哪怕是你不来。我也要创建。
