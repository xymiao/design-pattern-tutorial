# 设计模式之工厂模式（Factory）

工厂模式： Factory ，也可以叫做工厂方法。最核心的概念就是让创建对象和使用对象进行分离。并且使用的时候，引用其对应的抽象方法。 

来用一个实际的例子，来进行举例。

我有一个数据库 MySQL，其中与对应的字段。现在要根据字段的类型，转换成对应的 Java 对应的类型。

最终为了实现一个 MySQL 字段 to  Java 属性的过程。

如果使用面向过程的思考方式。

1. 首先要知道数据对应的字段类型。用几个常用的代替。
2. 判断是什么类型，转换成什么类型。
3. 根据类型进行条件判断，存在就返回对应的类型名称，否则返回异常。

```java
public class PopDemo {
    public static void main(String[] args) {
        String dbTypeName = "int";
        String typeName = new PopDemo().handle(dbTypeName);
        System.out.println("数据库字段类型为： " + dbTypeName
                + ", Java 的类型为：" + typeName);
    }

    public String handle(String dbFiledTypeName) {
        String javaTypeName;
        dbFiledTypeName = dbFiledTypeName.toLowerCase();
        if ("int".equals(dbFiledTypeName)) {
            javaTypeName = "Integer";
        } else if ("varchar".equals(dbFiledTypeName)) {
            javaTypeName = "String";
        } else {
            throw new RuntimeException("未定义对应关系");
        }
        return javaTypeName;
    }

}
```

执行的结果为： 

```sh
数据库字段类型为： int, Java 的类型为：Integer
```

这是最简单的代码执行。现在又有新的类型来了。

```mysql
CHAR
TEXT
TINYINT
BIGINT
```

那就需要，在上面的代码上加上对应的条件判断。这里有人说了，这里可以使用 switch 啊。不纠结这些技术细节，讨论的是实际代码中因为需求的变化，进行的调整。

最终的代码变成如下：

```java
public String handle(String dbFiledTypeName) {
    dbFiledTypeName = dbFiledTypeName.toLowerCase();
    String javaTypeName;
    if ("int".equals(dbFiledTypeName) ||
       	"tinyint".equals(dbFiledTypeName)) {
        javaTypeName = "Integer";
    } else if ("varchar".equals(dbFiledTypeName) ||
               "char".equals(dbFiledTypeName) ||
               "text".equals(dbFiledTypeName)) {
        javaTypeName = "String";
    } else if ("bigint".equals(dbFiledTypeName)) {
        javaTypeName = "Long";
    } else {
        throw new RuntimeException("未定义对应关系");
    }
    return javaTypeName;
}
```

这里只展示有变化的地方， main方法不会有任何变化。这也是实际开发中会使用的编码习惯，调用的时候使用很简单的代码进行调用，后续的调整一般不会动调用方式。

从这里开始，就需要频繁的修改 handle。 如果现在有一个需求，除了返回 Java 的数据类型名称，还需要对应的全类名，也就是要知道该类型的引用。不同的语言会有不同的引用方式。这里演示 Java，其他的高级语言也同样适用。

这个时候的逻辑就很复杂了， 还要判断是否是 JDK 基础包下， 也就是 `java.lang` 的包下，因为在该包下，是不需要使用 `import` 进行引用的。

最终的代码编程如下所示：

```java
public static void main(String[] args) {
    String dbTypeName = "int";
    Map<String, String> handle = new Pop2Demo().handle(dbTypeName);
    handle.forEach((k, v) -> {
        System.out.println("k = " + k + ", v = " + v);
    });

}

public Map<String, String> handle(String dbFiledTypeName) {
    dbFiledTypeName = dbFiledTypeName.toLowerCase();

    Map<String, String> map = new HashMap<>();
    switch (dbFiledTypeName) {
        case "int":
        case "tinyint":
            map.put("javaTypeName", "Integer");
            map.put("classFullName", "java.lang.Integer");
            map.put("baseFlag", "1");  //魔法值，1 是基础包 2 不是基础包。
            break;
        case "varchar":
        case "char":
        case "text":
            map.put("javaTypeName", "String");
            map.put("classFullName", "java.lang.String");
            map.put("baseFlag", "1");
            break;
        case "bigint":
            map.put("javaTypeName", "Long");
            map.put("classFullName", "java.lang.Long");
            map.put("baseFlag", "1");
            break;
        default:
            throw new RuntimeException("未定义对应关系");
    }
    return map;
}
```

执行之后输出的结果： 

```sh
k = baseFlag, v = 1
k = javaTypeName, v = Integer
k = classFullName, v = java.lang.Integer
```

这个时候，如果我们把所有的 MySQL 数据类型都写上，光类型都有 30 种之多，这个方法就会编程 30 * n 的提及，随随便便上 300 行以上的代码。

这个时候， 我们就可以使用工厂方法进行改造。
